# agy-review

**Независимый рецензент, который обязан подтверждать свои выводы.** Код-ревью, ревью безопасности, делегирование задач и перевод силами Google Antigravity (`agy`) из Claude Code, Codex или любого терминала. Только чтение, без запросов разрешений, и каждая находка сверяется с вашим реальным кодом, прежде чем вы её увидите.

## 1. Что вы получаете

| Навык (Claude Code / Codex) | Команда (Claude Code) | Что делает |
|---|---|---|
| `agy-review` / `review` | `/agy-review:review` | оценочное ревью изменений в git, ветки, файла, диапазона строк, одной функции или фрагмента |
| `agy-security` / `security` | `/agy-review:security` | ревью безопасности: OWASP/CWE, эксплуатируемость, сценарий атаки, сканер секретов и опасных паттернов, вызывающий и вызываемый код как контекст |
| `agy-proxy` / `proxy` | `/agy-review:proxy` | передайте Antigravity любую самодостаточную задачу (переписать, резюмировать, составить черновик, извлечь данные) и получите результат |
| `agy-translate` / `translate` | `/agy-review:translate` | перевод с учётом тона, аудитории и глоссария; проверяет, что код, URL, плейсхолдеры и структура сохранились |
| `agy-models` / `models` | `/agy-review:models` | список моделей в вашем agy, выбор одной, сохранение для проекта или глобально, настройка усилия (effort) |
| `setup`, `verify` | `/agy-review:setup`, `:verify` | проверка предварительных требований, установка защитного хука только для чтения, доказательство на вашей машине, что запись заблокирована |

Субагенты для Claude Code: `agy-reviewer`, `agy-security`, `agy-worker`. Всё это один репозиторий и один скрипт (`plugins/agy-review/scripts/agy-review.mjs`). Сервера нет, и нет никакой учётной записи, кроме вашего собственного входа в Antigravity.

## 2. Почему отчёту можно доверять

Языковая модель, проверяющая код, иногда выдумывает проблему. Этот инструмент не принимает ничего на веру.

1. Рецензент обязан вернуть строгий JSON-отчёт (обеспечивается через `--json-schema`). Каждая находка содержит **точный фрагмент кода**, к которому относится.
2. Скрипт ищет эту цитату в реальном файле. **Не найдена: находка отклоняется** и выводится отдельно. **Найдена в другой строке: номер строки исправляется.** Цитаты, слишком короткие или общие, чтобы что-либо доказывать (`return null;`, `}`), отклоняются. Цитата, совпадающая с несколькими местами вдали от указанной строки, отклоняется как неоднозначная.
3. Вердикт, счётчики и CI-шлюз **вычисляются скриптом** только по проверенным находкам и никогда не копируются у модели.
4. Отсутствие проверенных находок **не** означает одобрения: если находки были отклонены, модель не согласилась, не охватила код или одна из нескольких моделей дала сбой, вердикт будет `inconclusive`, а код выхода 4.
5. Находки вне запрошенных строк помечаются и никогда не влияют на шлюз. Находки с низкой уверенностью выводятся, но не учитываются.
6. Серьёзность (влияние) и приоритет (когда исправлять) разделены и согласованы: critical всегда P0, nit всегда P3, находки о стиле никогда не выше low.

Что всё ещё возможно: верная цитата с неверным выводом. Цитата доказывает, что код существует, но не что рассуждение правильное; поэтому у каждой находки есть конкретный сценарий и поэтому перед действиями стоит прочитать указанные строки.

Реальный пример: этот инструмент на небольшом файле с двумя заложенными ошибками (Claude Sonnet 4.6 через agy): 4 проверенные находки в правильных строках с CWE-89, CWE-78, CWE-22 и CWE-369, покрытие 100 %, один дубликат отброшен, а сканер независимо пометил те же две строки.

## 3. Статус: что проверено, а что нет

| Проверка | Результат |
|---|---|
| Модульные и конвейерные тесты (`npm test`): привязка к коду, область, вердикт, дедупликация, поиск символов, цели, конфигурация, модели, задачи, перевод, безопасность, редактирование секретов | 50 тестов, все проходят, с поддельным `agy` (включая агентный конвейер, обнаружение изменений дерева, сбойную модель и шлюз `verify`) |
| Защитный хук (разрешённые и запрещённые команды, инструменты, трюки с кавычками, пути к учётным данным) | автоматические тесты, проходят |
| Манифесты Claude Code (`claude plugin validate`), плагин Antigravity (`agy plugin validate --strict`) | проходят |
| Codex 0.163.0: добавление маркетплейса, установка плагина, обнаружение навыков | проверено на Windows 11 |
| Статическое ревью, ревью безопасности и задачи на реальном agy 1.4.8 (Gemini 3.8 Flash и Claude Sonnet 4.6), запуск с Bun 1.3.14 | проверено на Windows 11; находки привязаны к правильным строкам |
| Два независимых ревью дизайна и кода (Opus: 25 находок; Codex: 28 находок), подтверждённые исправлены, для каждой добавлен регрессионный тест | выполнено, см. changelog |
| **Агентные ревью (`agy --dangerously-skip-permissions` плюс хук, блокирующий реальную запись)** | **автором не запускались** |

Последняя строка важна для безопасности и зависит от версии вашего agy, поэтому запустите `verify` один раз после установки и после каждого обновления agy (раздел 6). Статические ревью, ревью безопасности символа/файла/фрагмента, задачи и переводы никогда не используют этот флаг и не могут ничего записать.

Проверено с agy 1.4.8, Codex CLI 0.163.0, Bun 1.3.14 и Node 24, Windows 11. На macOS и Linux должно работать (agy использует `~/.gemini/config/plugins` на всех платформах), но не проверялось.

## 4. Требования

Больше ничего: никаких других плагинов, никаких других CLI-инструментов.

| Нужно | Зачем | Как получить | Как проверить |
|---|---|---|---|
| Antigravity CLI `agy` | выполняет работу | https://antigravity.google/cli, затем один раз запустите `agy` и войдите в систему | `agy --version` |
| Bun (рекомендуется) **или** Node.js 18.18+ | запускает скрипт и защитный хук | https://bun.sh или https://nodejs.org | `bun --version` / `node --version` |
| git | git-цели и поиск связанного кода | https://git-scm.com | `git --version` |
| Claude Code **или** Codex **или** любой терминал | откуда вы обращаетесь | их руководства по установке | `claude --version` / `codex --version` |

Bun используется по умолчанию во всех инструкциях и в защитном хуке (`bun guard.mjs || node guard.mjs`); Node работает так же. Использование Antigravity расходует вашу собственную квоту. Ревью может занять от нескольких секунд до нескольких минут.

## 5. Установка

Выберите используемую среду; несколько сред могут делить один и тот же скрипт и хук.

### 5a. Claude Code

```text
/plugin marketplace add Ealireza/agy-review
/plugin install agy-review@agy-review
/agy-review:setup
/agy-review:verify
```

`/agy-review:setup` проверяет agy, git и защитный хук и устанавливает хук в `~/.gemini/config/plugins/readonly-review`. `/agy-review:verify` даёт живое доказательство безопасности.

### 5b. Codex

```bash
codex plugin marketplace add Ealireza/agy-review
codex plugin add agy-review@agy-review
```

Перезапустите Codex и задайте просьбу обычным языком: «Проверь настройку ревью через Antigravity», «Проверь мои изменения с помощью Antigravity», «Сделай ревью безопасности функции saveUpload», «Переведи README.md на немецкий, дружелюбный тон».

1. **Установите защитный хук один раз из обычного терминала** (он пишет в `~/.gemini/config/plugins`): `bun ~/.codex/plugins/cache/agy-review/agy-review/1.0.0/scripts/agy-review.mjs --install-guard` (Windows: `%USERPROFILE%\.codex\plugins\cache\agy-review\agy-review\1.0.0\scripts\agy-review.mjs`). Хук нужен только для агентных git-ревью.
2. **Песочница Codex должна позволять agy работать:** исходящая сеть, доступ на запись в `~/.gemini/antigravity-cli` и локальный сокет localhost. С `workspace-write`, скорее всего, понадобится в `~/.codex/config.toml`:

   ```toml
   [sandbox_workspace_write]
   network_access = true
   writable_roots = ["/home/you/.gemini/antigravity-cli"]   # Windows: "C:\\Users\\you\\.gemini\\antigravity-cli"
   ```

   Если что-то всё ещё заблокировано, навык называет недостающий доступ и останавливается; он никогда не расширяет разрешения сам. Корректность работы agy внутри вашей песочницы Codex автор проверить не смог, поэтому запустите `verify` и изнутри Codex.

### 5c. Обычный терминал

```bash
git clone https://github.com/Ealireza/agy-review
cd agy-review
bun plugins/agy-review/scripts/agy-review.mjs --check
bun plugins/agy-review/scripts/agy-review.mjs --install-guard
bun plugins/agy-review/scripts/agy-review.mjs --verify
# then, from inside any git repository (use node instead of bun if you prefer):
bun /full/path/to/agy-review/plugins/agy-review/scripts/agy-review.mjs --security --symbol saveUpload
```

Совет: `alias agyr='bun /full/path/to/agy-review/plugins/agy-review/scripts/agy-review.mjs'`.

### 5d. Только сторона Antigravity

Защитный хук — обычный плагин Antigravity. Скопируйте `plugins/agy-review/antigravity-plugin/readonly-review` в `~/.gemini/config/plugins/readonly-review` или запустите `--install-guard`; проверьте командой `agy plugin list`. Он ничего не делает, пока запрос не содержит `AGY_READONLY_REVIEW`, поэтому ваши обычные сессии agy не меняются. Также поставляется навык `readonly-code-review` для интерактивного agy.

## 6. Первый запуск: проверьте на своей машине

Запустите один раз после установки и после каждого обновления agy: `/agy-review:verify`, навык Codex `verify` или `--verify`. Он делает один небольшой живой вызов agy во временной папке: чтение файла (должно работать), запись файла, перенаправление в файл и удаление файла (всё это должно быть заблокировано). Ожидаемый результат:

```text
PASS  read allowed
PASS  file write blocked
PASS  redirect blocked
PASS  delete blocked
PASS  guard actually fired

Verified: reads work, writes are blocked.
```

Любой `FAIL` завершается сообщением `NOT VERIFIED`, и агентные ревью остаются отключёнными: создайте issue с выводом и вашим `agy --version`. Успешный `verify` записывается именно для этого хука и этой версии agy; **агентные ревью отказываются запускаться без него**, а обновление agy или хука аннулирует его, поэтому после обновлений запускайте `verify` снова. Статическим режимам он не нужен.

## 7. Использование

Запускайте из корня репозитория.

### 7a. Ревью: выбор цели

| Что вы хотите проверить | Используйте | Режим |
|---|---|---|
| незакоммиченную работу | ничего | агентный, только чтение |
| ветку / индексированные изменения / один коммит | `--base main` / `--staged` / `--commit <sha>` (+ `--paths a,b`) | агентный, только чтение |
| файл или диапазон | `--file src/a.kt` или `--file src/a.kt:40-80` (можно повторять) | статический |
| одну функцию или класс | `--symbol parseConfig` (+ `--file`, если имя неоднозначно) | статический |
| код, существующий только в памяти | `... \| agy-review --stdin --lang python --name snip.py [--start-line N]` | статический |
| любое из перечисленного плюс разрешение смотреть другие файлы | добавьте `--agentic` | агентный, только чтение |

*Статический режим*: скрипт сам читает и нумерует код, а модель не получает инструментов, поэтому ничего нельзя затронуть и ничего нельзя выдумать о файлах, которые ей не показывали. *Агентный режим*: рецензент сам читает репозиторий через защитный хук, который блокирует любую запись.

Помогите рецензенту: `--context "what this code must do"`, `--focus "concurrency, error handling"` (или слова в конце), `--context-lines N`.

Вывод: по умолчанию Markdown; `--format json` для машин; `--output file`; `--fail-on high` (код выхода 10, если есть проверенная находка уровня high или critical); `--previous old.json` помечает находки как новые, сохраняющиеся, исправленные или не упомянутые повторно.

```text
## Summary
**Verdict: request changes**. ...
Target: app.py:1-19 | mode: static | model: Claude Sonnet 4.6 | effort: model default (...)
Findings: 4 verified (2 critical, 1 high, 1 medium ...).
### Critical
- **SQL injection** - `app.py:6` [P0 | security | confidence high | CWE-89] (id 9a9fb99468)
  Evidence:
      cur.execute("SELECT * FROM users WHERE name = '" + name + "'")
  Problem: ...   Fix: ...
```

### 7b. Ревью безопасности

`--security` (навык `agy-security`, команда `/agy-review:security`, субагент `agy-security`) работает со всеми перечисленными выше целями и добавляет: метод моделирования угроз (от недоверенного источника к опасному приёмнику с промежуточными средствами контроля), сопоставление с OWASP Top 10 (2021) и CWE, `exploitability` (`demonstrated`, `likely`, `conditional`, `theoretical`), `attack_scenario`, `data_flow`, сканер секретов и около 25 классов опасных паттернов без участия модели, а также **связанный код**: что вызывает цель и кто вызывает её.

- Жёстко прописанный секрет (приватный ключ, AWS, GitHub, Stripe, Slack, Google) **редактируется до отправки чего-либо модели** и сообщается как находка по паттерну.
- `cve` в отчёте — утверждение модели и всегда помечается `cve_verified: false`: подтвердите его в NVD или с помощью `osv-scanner` / `npm audit` / `pip-audit`. Инструмент никогда не выдумывает и не проверяет CVE.
- «Claude написал код, проверьте его и соседние части»: скопируйте готовое правило из `examples/` в ваш `CLAUDE.md` или `AGENTS.md` либо установите необязательный Stop-хук или pre-commit-хук. Подробности и рецепты цепочек: [SECURITY-REVIEW.md](SECURITY-REVIEW.md).

### 7c. Задачи: `agy-proxy`

```bash
bun agy-review.mjs --task "Summarise in 5 bullets for non-technical readers" --input notes.md
cat draft.txt | bun agy-review.mjs --task "Rewrite more friendly" --stdin --format json
```

Модель получает только переданный вами текст и никаких инструментов. Текстовый режим печатает только ответ; в stderr сообщаются модель и effort.

### 7d. Перевод: `agy-translate`

```bash
bun agy-review.mjs --preset translate --to Persian --tone friendly --audience "new developers" --glossary glossary.json --input README.md --output docs/README.fa.md
```

Параметры: `--from`, `--variant` (pt-BR, zh-TW, de-CH ...), `--tone` (formal, neutral, friendly, casual, technical, marketing, literary, legal), `--audience`, `--glossary` (JSON `{"repo":"مخزن","API":"="}` или CSV; `=` сохраняет термин), `--keep a,b`, `--notes`, `--strict`. Длинные тексты разбиваются по пустым строкам (никогда внутри блока кода) и переводятся по частям. После перевода скрипт проверяет, что блоки кода, встроенный код, URL, плейсхолдеры (`{{x}}`, `${x}`, `%s`), теги и заголовки совпадают с источником, и сообщает о каждом расхождении (`--strict` превращает расхождение в код выхода 11). Навыки сначала проводят с вами опрос о тоне, аудитории и терминах, спрашивая только то, что не могут определить сами. Машинные проверки не оценивают беглость; важные тексты стоит показать носителю языка.

### 7e. Модели и effort

```bash
bun agy-review.mjs --list-models                    # id and name, * marks your selection
bun agy-review.mjs --set model=claude-sonnet-4-6    # this project (.agy-review.json); add --global for all projects
bun agy-review.mjs --set models=gemini-3.8-flash-high,claude-sonnet-4-6   # cross-check: findings both report are marked
bun agy-review.mjs --show-config
```

Для отдельного запуска: `--model <id|name>`, `--models a,b`, `--effort auto|low|medium|high|xhigh|max`. Приоритет: командная строка, файл проекта, файл пользователя, значение agy по умолчанию. `--effort auto` (по умолчанию) — детерминированный и объяснимый выбор: ревью масштабируются по объёму кода в области проверки (чувствительный к рискам фокус, например безопасность, добавляет один шаг), задачи — по формулировке (механические преобразования low, требующие рассуждений high) и длине входных данных; `max` никогда не выбирается автоматически. Некоторые модели не принимают `--effort`; тогда инструмент использует значение модели по умолчанию и сообщает об этом. Если контентный фильтр Gemini отклоняет запрос, а вы не указали модель, инструмент один раз повторяет попытку с моделью не из семейства Gemini и сообщает об этом.

### 7f. Параметры и коды выхода

`bun agy-review.mjs --help` перечисляет всё. Коды выхода: `0` ок · `1` ошибка, тайм-аут или не поддающийся разбору ответ · `2` ошибка использования или отсутствует предварительное требование · `3` рабочее дерево изменилось во время агентного ревью · `4` неопределённый или неполный результат (**не успех**) · `10` не пройден шлюз `--fail-on` (отчёт корректен) · `11` проверка перевода не пройдена с `--strict`. Если применимо несколько, `3` приоритетнее `10`, а `10` приоритетнее `4`; отчёт записывается во всех случаях, кроме `1` и `2`, поэтому читайте в нём `verdict` и `incomplete`. Чистое рабочее дерево не является ошибкой: инструмент печатает "No changes to review" и завершается с кодом 0, не обращаясь к модели.

## 8. Использование из агентов, субагентов и циклов

Каждый навык — это обычный вызов CLI со стабильным JSON, поэтому его может использовать любой агент: запустите субагента `agy-reviewer`, `agy-security` или `agy-worker` в Claude Code, вызывайте навыки в Codex или вызывайте скрипт из любого фреймворка.

```bash
# implement -> review -> fix, repeated at most 5 times
bun agy-review.mjs --security --symbol applyDiscount --context "applies at most one coupon" --format json --output r.json --fail-on high
# exit 0: done   10: fix the P0/P1 findings and re-run with --previous r.json   4: inconclusive, not a pass   1/2: stop and report
```

Рецензенту никогда не сообщается, что вы изменили, поэтому каждый раунд остаётся независимым. Полный контракт, поля JSON, рецепты циклов и шаблоны параллельного запуска: [AGENTS.md](AGENTS.md).

## 9. Модель безопасности

**Статические ревью, ревью безопасности символа/файла/фрагмента, задачи и переводы** запускают agy без каких-либо флагов разрешений и без инструментов в пустой временной папке: agy не может читать или записывать ваши файлы; уходят только данные, которые скрипт поместил в запрос (с отредактированными распознанными секретами).

**Агентные ревью** (git-цели или `--agentic`) запускают agy с `--dangerously-skip-permissions`, чтобы ничто не ждало подтверждения, и опираются на защитный хук `PreToolUse` (`guard.mjs`), который проверяет каждый вызов инструмента и **по умолчанию запрещает**:

- разрешено: инструменты просмотра и поиска файлов; команды оболочки, одиночные или цепочкой, составленные только из `git`-подкоманд только для чтения, `rg`, `grep`, `cat`, `ls`, `head`, `tail`, `wc`, `find` (без `-delete`/`-exec`), PowerShell `Get-*`, `Select-String` и ещё нескольких (список в `guard.mjs`);
- запрещено: любые инструменты записи/редактирования/ноутбуков/изображений/планирования/субагентов/браузера/веба/MCP и любой неизвестный инструмент; перенаправление, `$(...)`, обратные кавычки, блоки скриптов, конструкции типа `eval`; `git commit/push/checkout/reset/...`; интерпретаторы и менеджеры пакетов; `curl`, `ssh`; чтение хранилищ учётных данных (`.ssh`, `.aws`, `.gnupg`, приватные ключи);
- если хук падает, он запрещает; скрипт отказывается запускать агентный прогон, если хук не установлен, не идентичен поставляемому **и для этого хука и этой версии agy не записан успешный `--verify`**; до и после прогона он снимает отпечаток `git status`, отслеживаемых и индексированных диффов и содержимого каждого неотслеживаемого файла и завершается с кодом 3 с предупреждением, если что-либо отличается.
- **Секреты в агентном режиме нельзя отредактировать** до того, как рецензент прочитает файлы. Инструмент обнаруживает их, предупреждает и перечисляет в `limitations`; смените их или проверяйте с `--file` / `--symbol`, где они редактируются заранее.

Чем это не является:

- **Это не песочница уровня ОС.** Хук фильтрует имена инструментов и текст команд; собственная песочница agy доступна не везде. Намеренная prompt injection, спрятанная в проверяемом коде, может искать форму команды, которую фильтр пропустит. Проверка до/после выявляет изменённые отслеживаемые файлы и новые файлы, но не чтение.
- **Ваш код отправляется модели Google**; чтение не ограничено, кроме путей к учётным данным. Файлы `.env` в репозитории доступны для чтения агентным ревью. Не проверяйте код, которым вы не вправе делиться.
- git может запускать внешние программы diff или textconv, настроенные в репозитории: проверяйте только репозитории, которым доверяете.
- Находки могут быть неверными или неполными, а «нет находок» никогда не означает «безопасно».

## 10. Устранение неполадок

| Симптом | Причина и решение |
|---|---|
| `Missing: agy CLI` | установите Antigravity CLI и один раз запустите `agy`, чтобы войти; `agy --version` должен работать в оболочке, запускающей плагин |
| `Missing: read-only guard - missing/outdated` | запустите setup (`/agy-review:setup`, навык Codex `setup` или `--install-guard`); хук нужен только агентным ревью |
| `Not inside a git repository` (код 2) | перейдите (`cd`) в корень репозитория или проверяйте код с `--file` / `--symbol` / `--stdin` |
| Вердикт `inconclusive`, код 4 | не успех: находки были отклонены, модель не согласилась или не охватила код, либо одна модель дала сбой. Сузьте область, добавьте `--context` или попробуйте другую `--model` |
| `blocked by Gemini's filters` | сработал фильтр безопасности Gemini (часто для запросов о безопасности). Без `--model` инструмент повторяет попытку с моделью не из семейства Gemini; иначе выберите её через `--model` |
| `--effort is not supported for model` | обрабатывается автоматически (используется значение модели по умолчанию, об этом сообщается) |
| Пустое ревью, код 1 | проверьте вход и квоту командой `agy -p "say hi"`; увеличьте `--timeout` для больших целей |
| Код 3 / рабочее дерево изменилось | что-то изменило ваши файлы во время агентного ревью (редактор, сборка или обход хука). Проверьте `git status` и `git diff`; если вы их не меняли, считайте это событием безопасности |
| Много отклонённых находок | модель процитировала код, которого там нет. Иногда это ожидаемо; такие находки никогда не учитываются. Используйте более сильную `--model` или более узкую область |
| `--symbol`: "defined in several places" или "not found" | укажите `--file` или используйте `--file path:A-B`. Поиск эвристический (сопоставление скобок/отступов), а не парсер |
| Codex: "blocked by sandbox" | см. 5b: должны быть разрешены сеть, запись в `~/.gemini/antigravity-cli` и сокет localhost |
| Windows: `agy` или `bun` не найден внутри Claude/Codex | у оболочки инструмента другой `PATH`; запускайте её из оболочки, где команда работает |
| `verify` выводит FAIL | не используйте агентные ревью для важного кода; создайте issue с выводом и `agy --version` |

## 11. FAQ

**Меняет ли он мой код?** Нет. Статические режимы не могут; агентный режим блокирует запись и предупреждает, если ваше дерево потом отличается. Он никогда ничего не коммитит, не прячет в stash и не переключает.

**Bun здесь быстрее Node?** Измеримо нет. На Windows-машине автора запуск занял около 56 мс с Node и 64 мс с Bun, а защитный хук — около 60 мс против 57 мс; ревью занимает десятки секунд, и это время модели. Bun — документированное значение по умолчанию; Node 18.18+ работает так же. Оба покрываются одним и тем же кодом.

**Это стоит денег?** Плагин бесплатный. Каждое ревью расходует вашу квоту Antigravity.

**Какие файлы видит Antigravity?** Статические режимы: только код, который отправляет скрипт (плюс ограниченный связанный код для `--security`). Агентные режимы: всё, что он прочитает в репозитории, и любое место на диске, кроме путей к учётным данным.

**Может ли он исправлять находки?** Никогда. Исправляет другой агент или вы; рецензент только проверяет, поэтому остаётся независимым.

**Может ли он проверить pull request на GitHub?** Переключитесь на ветку локально и используйте `--base`. Доступа к GitHub API нет.

**Почему не добавить команды в список разрешённых в настройках agy?** Проверено: в headless-режиме agy сопоставляет разрешения из нескольких слов точно (`git status` да, `git status --short` нет), а «allow» от хука не переопределяет проверку разрешений. Хук может надёжно только запрещать, отсюда skip-permissions плюс хук с запретом по умолчанию для агентного режима и полное отсутствие инструментов для статического.

**Можно ли добавить разрешённые команды или правила сканера?** Отредактируйте `CMDS` / `GIT_OK` в `guard.mjs` или `RULES` в `lib/security.mjs`, запустите `npm test`, затем `--install-guard`.
